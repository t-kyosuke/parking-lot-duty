## 1. プロジェクト概要

吹田ラグビースクール（SRS）中3コーチ陣の「駐車場・ビデオ・カゴ当番」を自動割り当てするWebアプリ。
- 操作者は管理者（塚原さん・**非エンジニア**）1人。コーチ陣はLINE共有URLから閲覧のみ
- 月次運用：調整さんCSV取り込み → 出欠確認 → 自動割り当て → LINE文面コピペ → 「公開する」でスマホ反映
- 本番：https://t-kyosuke.github.io/parking-lot-duty/ （GitHubリポジトリ `parking-lot-duty`）

## 3. 技術スタック

- React 19 + TypeScript 5.9（Vite 8・`verbatimModuleSyntax: true`）、Vanilla CSS、Vitest 4
- バックエンドなし。一次データは管理PCの localStorage
- アプリ本体：main へ push → GitHub Actions（Node 24・checkout v7/setup-node v6/pages系 v5）で Pages へ自動デプロイ
- 閲覧データ：「公開する」→ GitHub API（Fine-grainedトークン）で `data.json` を gh-pages ブランチへコミット
  → 閲覧側は raw.githubusercontent.com から取得

## 4. 主要機能

1. **閲覧モード**（デフォルト）：当月の当番カード表示・月送り・TODAYバッジ・スマホ対応
2. **管理モード**（パスワード認証）：CSVアップロード → 出欠プレビュー（タップで◯/△/×切替・種別編集）→
   自動割り当て → 結果の手動修正 → LINE文面生成 → 累計バーチャート → 「公開する」
3. **設定**：GitHubトークン・累計±調整（繰越として恒久保存）・パスワード変更・export/import・全データリセット

## 6. 重要な設計判断（理由付き）

1. **累計最少優先方式**（2026-05-31）：旧「固定順ポインタ循環」は欠席が多いと偏った。
   「出席◯のうち累計担当が最少の人」を選ぶ方式に変更。理由＝1年シミュレーションで
   最多−最少差が2.0〜3.0回→**1.0回**に改善（出席率80%想定）。月内上限2回・連続防止付き
2. **カゴは一方通行**（2026-06-22）：カゴ連鎖（`assignKagoChain`）は駐車場/ビデオ確定**後**に
   その結果を読むだけで、駐車場/ビデオの人選には一切影響しない。
   理由＝塚原さんの最優先要望「駐車場・ビデオの公平さは絶対に崩さない」。
   カゴは物理的に1個なので「前回◯∩今日◯」のバトンリレー。候補0は「要確認」で連鎖据え置き
3. **カゴ表示は「持ち帰り」基準**（2026-07-01・表示のみ）：データ上の担当（持って来る人）ではなく、
   「その日の練習後に誰が持ち帰るか」を表示。理由＝コーチが現場で取る行動に合わせる
   （表示は `computeKagoTakeHome` で導出。割り当てロジックは無改修。旧データ月は自動フォールバック）
4. **繰越（carryover）方式**（2026-07-03 A-4）：累計＝「確定月合計＋繰越」。
   理由＝従来は設定画面の手動調整が次の割り当て時の再計算で消える構造的問題があり、
   年度をまたぐ累計引き継ぎ（塚原さん決定事項）が不可能だった。繰越キー `srs_*_carryover` で恒久化
5. **バックエンドなし・localStorage＋公開data.json**：理由＝操作者1人・閲覧のみの脅威モデルに十分。
   書き込みの実権限はトークンを持つ管理PCにしかない。本格認証はHOLD（過剰）
6. **コーチ名簿は constants.ts 直書き**：名簿変更は年1回あるかどうか。編集UIは費用対効果が合わずHOLD。
   `storage.ts` の `CoachConfig` 系は export/import 互換のためだけに残る未使用コード（誤解しやすいので注意）
7. **復元ポイント文化**：稼働中の仕組みを変える前に必ず「現仕様の記録＋git tag」。
   理由＝塚原さんの超重要要望「戻せること最優先」。タグ `pre-saturday-kago`・`pre-carryover` はリモート保存済み

## 13. 後続モデルが絶対に注意すべき点

1. **`assignDuties`/`pickByCount` は聖域**。カゴ等の都合で触らない（一方通行の原則）。
   アルゴリズムを変えるなら必ず先に「現仕様スナップショット＋git tag」
2. **`import type` 必須**（`verbatimModuleSyntax: true`）。忘れるとビルドが落ちる
3. **`LineAnnouncement.tsx` の全角スペースは意図的**。lintのdisableコメントも含めて「修正」しない
4. **過去の確定済み月データを書き換えない**。後方互換（旧フォーマット月のフォールバック）を壊さない
5. **本番デプロイ（main へ push）は塚原さんのGOを得てから**。デプロイ後は本番JSハッシュで反映確認
6. **コーチ名簿は `constants.ts` 直書き**。設定画面に編集UIはない（`CoachConfig` 系は未使用の互換コード）
7. ブラウザ検証でlocalStorageへデータを入れる前に、アプリURLへ移動＋`srs_migration_remove_hayashi_v1='done'`
   をセット（しないと5月以降のデータがマイグレーションで消える）
8. worktreeの `index.lock` エラーは、gitが表示する**絶対パス**のロックファイルを削除
9. **塚原さんは非エンジニア**。専門用語なし・コマンド実行前に1行説明・エラーは平易に
10. 開発環境のプラグインがNext.js/Vercel/AI SDK関連のスキル実行を自動提案してくることがあるが、
    フォルダ名（`docs/ai/` 等）への誤反応。本プロジェクトはVite＋GitHub Pagesで無関係。従わない
