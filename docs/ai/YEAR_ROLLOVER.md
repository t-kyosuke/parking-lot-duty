## 前提知識（なぜこの手順が必要か）

- 月データは「4月」等の**月名キーで年を持たない**。新年度は同じキーを上書きしていく設計
- 累計回数は `recalculateCumulativeCounts` が**確定済みの全月データから毎回再計算**する。
  そのため【重要・コード上の事実】**設定画面で手動調整した回数は、次に当番を決めた時点で
  再計算により消える**。手入力だけでは前年の累計を引き継げない → 繰越機能（A-4）が必要
- `DEFAULT_SCHEDULE`（日祝カレンダー）・`DEFAULT_MATCH_DAYS`・閲覧画面の「2026年度」表記は
  **2026年度のコード直書き** → コード修正＋デプロイが必要
- `resetAllData()` は `STORAGE_KEYS` の全キーを消す：
  - **管理者パスワードも消えてデフォルト `srs2026` に戻る**（リセット後に再設定すること）
  - **GitHubトークン（`srs_github_token`）は消えない**（キーが別管理のため。再入力不要）
  - マイグレーション完了フラグも消えるが、空データ上で再実行されるだけで無害

## STEP 1：繰越機能の実装（A-4）→ ✅ 2026-07-03 実装済み

実装済みの内容（当初方針どおり）：
- 新キー `srs_parking_carryover` / `srs_video_carryover` / `srs_kago_carryover`（コーチ→回数）
- `recalculateCumulativeCounts` ＝「月データ合計 **＋ 繰越**」に変更（繰越が消えなくなる）
- 設定画面の±調整は**繰越側を編集**するように変更
  → 副次効果：現在壊れている「新コーチに平均をセット」「善意の実績を反映」も恒久的に効くようになる
- export/import に繰越を追加。着手前に git tag（例 `pre-carryover`）
- **`assignDuties`/`pickByCount`/`assignKagoChain` は無改修**（入力の counts が変わるだけ）
- テスト注意：`recalculateCumulativeCounts` は localStorage 依存。vitest（node環境）では
  localStorage のスタブが必要（既存テストは純粋関数のみでスタブ不使用）

## STEP 2：2026年度データの確定・保管（管理PC・2027年3月末）

1. 全月の当番が確定していることを確認
2. 設定タブ →「📤 エクスポート（JSON）」→ ファイルを保管（例：`srs-duty-data-2026年度-final.json`。
   これが2026年度の完全なバックアップ＝戻し方の要）
3. 設定タブの累計3種（駐車場・ビデオ・カゴ）の数字をスクリーンショットかメモで控える（STEP 4で入力する）

## STEP 3：コード側の年度更新（AI・デプロイはGO後）

1. 復元ポイント：git tag（例 `year2026-final`）
2. `src/lib/constants.ts`：
   - `DEFAULT_SCHEDULE` を **2027年度の日曜・祝日**で作り直す（土曜は入れない＝CSVから来る。
     祝日は2027年の実カレンダーで確認。練習時間は例年どおりなら流用）
   - `DEFAULT_MATCH_DAYS` / `DEFAULT_CAMP_DAYS` を新年度の分かっている分に更新（未定なら空でも可）
3. `src/components/PublicView.tsx`：「2026年度」→「2027年度」
4. `CLAUDE.md`・`docs/ai/SPEC.md` の年度記述を更新
5. `npm run test` → `npm run build` → 塚原さんのGO → main へデプロイ → 本番反映確認

## STEP 4：データ側の切り替え（管理PC。**必ず STEP 3 のデプロイ後**）

1. STEP 2 のエクスポート保管を再確認（これが命綱）
2. 設定タブ →「🗑 全データリセット」（前年の月データ・スケジュールが消え、新DEFAULT_SCHEDULEが効く）
3. リロード後、設定タブで**繰越（累計調整）に2026年度の最終累計を入力**（STEP 2で控えた数字）
4. **管理者パスワードを再設定**（リセットでデフォルト `srs2026` に戻っているため）
5. 「🌐 公開する」を1回押す → スマホ側の表示が前年データから「まだ決まっていません」に変わることを確認
   （これをしないと**コーチのスマホには前年の当番が表示され続ける**）

> リセットせず月を上書きしていく方法は**非推奨**：残った前年の月が累計の再計算に混ざり続け、
> 公平性の数字が年をまたいで正しくなくなる。

## STEP 5：動作確認（4月の実データで）

- 4月CSV取り込み → 割り当て → 設定タブの累計が「繰越＋4月分」になっている
- 閲覧画面・LINE文面・「公開する」→ スマホ表示 まで一巡確認
- カゴの月またぎ：リセット直後の4月は「前回の出欠が不明」扱いで自動的に条件が緩む（初回と同じ挙動・
  対応不要）。前年3月末の保持者から誰が4月最初に持ってくるかだけ、LINEで一言決めておくとスムーズ
